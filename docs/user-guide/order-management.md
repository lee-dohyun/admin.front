## 1. 이 기능으로 할 수 있는 일
주문을 상태·주문일·검색어(주문번호·주문자 이름·연락처·이메일)로 찾고, 한 주문의 상품·배송지·금액·배송·취소·반품·환불·진행 기록을 한 화면에서 본다. 고객 요청 등으로 주문을 통째로 되돌려야 할 때 상세 화면에서 「전체 환불」을 실행한다.

## 2. 시작하기 전에
- 직원 계정으로 <https://admin.posselect.com/login> 에 로그인한다. 메뉴에 「주문 관리」가 안 보이면 권한이 없는 것이다 — 시스템 관리자에게 「주문 관리」 역할을 요청한다.
- 전체 환불은 **되돌릴 수 없다.** 실행하면 바로 환불 기록이 생기고, 재고가 돌아오고, 고객에게 환불 안내 메일이 간다.
- 상품 일부만 돌려주는 부분 환불은 이 화면에서 하지 않는다. 고객이 마이페이지에서 취소·반품을 신청하면 「취소·반품 신청」 화면에서 처리한다(별도 설명서 `claim-review.md`).

## 3. 따라 하기
### 3-1. 주문 찾기
1. 메뉴 「주문 관리」를 연다 → 최신 주문부터 한 페이지에 20건씩 보이고, 표 위에 조건에 맞는 전체 건수(예: 「312건」)가 보인다.
2. 필요한 조건을 고른다.
   - 「상태」: 「전체」 또는 「결제 대기」「결제 완료」「배송 준비」「배송중」「배송완료」「주문취소」「환불완료」
   - 「주문일 시작」「주문일 끝」: 한국 날짜 기준이고 양 끝 날짜를 포함한다.
   - 「검색어」: 주문번호, 주문자 이름(일부만 써도 된다), 연락처, 회원 이메일 또는 비회원 연락 이메일.
3. 「조회」를 누른다 → 조건에 맞는 주문만 보인다. 없으면 「조건에 맞는 주문이 없습니다.」가 보인다.
4. 건수가 한 페이지를 넘으면 표 아래 「이전」「다음」으로 넘긴다. 가운데에 「현재 페이지 / 전체 페이지」가 보인다.
5. 조건을 모두 지우려면 「초기화」를 누른다.

검색 조건은 주소창에 남는다. 상세를 봤다가 「목록으로」를 누르거나 새로 고침해도 같은 조건·같은 페이지로 돌아온다. 주소를 다른 직원에게 보내면 같은 목록이 보인다.

### 3-2. 주문 상세 보기
1. 목록의 「주문번호」(예: 「#123」)를 누른다 → 주문 상세가 열린다.
2. 상세에서 볼 수 있는 것:
   - 「주문자·배송지」: 주문자, 받는 분, 배송지
   - 「상품」: 상품별 단가·수량·취소·반품 수량·금액, 상품 합계·등급 할인·배송비·결제 금액
   - 「배송」: 택배사·운송장 번호와 「배송중」/「배송완료」. 운송장이 없으면 「운송장이 아직 등록되지 않았습니다. 운송장 등록은 주문 목록에서 합니다.」
   - 「취소·반품·교환」: 고객 신청이 있을 때만 보인다. 신청 번호·유형·상품·사유·상태·환불 금액
   - 「환불」: 전체 환불한 주문이면 「전체 환불 금액 · 환불 시각 · 사유: …」
   - 「진행 기록」: 주문 접수·결제 완료·출고·배송 완료·신청 접수/처리·전체 환불의 시각
3. 「목록으로」를 누르면 들어오기 전의 검색 조건으로 돌아간다.

### 3-3. 전체 환불하기
1. 주문 상세의 「환불」 칸으로 간다. 「남은 결제 금액 N원을(를) 전부 환불하고 재고를 되돌립니다.」가 보이면 환불할 수 있는 주문이다.
2. 「환불 사유(고객에게 보내는 환불 안내 메일에 들어감)」에 사유를 적는다. 고객이 그대로 읽는다.
3. 「전체 환불」을 누른다 → 「주문 #N을(를) 전체 환불할까요? N원이 환불되고 재고가 돌아옵니다. 되돌릴 수 없습니다.」에서 확인을 누른다.
4. 화면이 새로 불러와지고, 제목 옆 상태가 「환불완료」로, 「환불」 칸에 「전체 환불 N원 · 시각 · 사유: …」가, 「진행 기록」 끝에 「전체 환불 N원」이 보이면 끝이다.

## 4. 입력 항목 설명
| 항목 | 필수 | 설명 | 입력 규칙 |
|---|---|---|---|
| 상태 | 아니요 | 이 상태의 주문만 본다 | 목록에서 고른다. 「전체」는 조건 없음 |
| 주문일 시작·끝 | 아니요 | 이 기간에 들어온 주문만 본다 | 한국 날짜, 양 끝 포함. 시작이 끝보다 늦으면 조회되지 않는다 |
| 검색어 | 아니요 | 주문번호·주문자 이름·연락처·이메일 중 하나라도 걸리면 보인다 | 이름·이메일은 일부만 써도 되고 대소문자를 가리지 않는다. 연락처는 숫자만(하이픈·공백은 있어도 무시) 쓴다. 주문번호는 정확히 일치해야 한다(앞의 「#」는 있어도 된다) |
| 환불 사유 | 전체 환불할 때 필수 | 고객에게 가는 환불 안내 메일에 들어간다 | 1~300자 |

## 5. 상태와 진행 흐름
| 상태(화면 표시) | 뜻 | 전체 환불 |
|---|---|---|
| 「결제 대기」 | 주문은 들어왔지만 결제 전이다 | 안 된다 — 「결제 전 주문은 환불할 수 없습니다.」 |
| 「결제 완료」 | 결제됐고 아직 출고 전이다. 목록에서 운송장을 등록한다 | 된다 |
| 「배송 준비」 | 출고를 준비 중이다 | 된다 |
| 「배송중」 | 운송장이 등록됐다. 목록에서 「배송완료 처리」를 한다 | 된다 |
| 「배송완료」 | 고객에게 도착했다 | 된다 |
| 「주문취소」 | 고객이 출고 전에 주문을 모두 취소했다 | 안 된다 — 「환불할 수 없는 상태입니다.」 |
| 「환불완료」 | 전체 환불이 끝났다 | 안 된다(이미 환불됨) |

## 6. 자주 보는 메시지와 해결 방법
| 화면 메시지(원문) | 원인 | 해결 |
|---|---|---|
| 「시작일이 종료일보다 늦습니다.」 | 「주문일 시작」이 「주문일 끝」보다 뒤다 | 날짜를 바로잡고 다시 「조회」 |
| 「조건에 맞는 주문이 없습니다.」 | 조건에 걸린 주문이 없다 | 조건을 줄이거나 「초기화」 |
| 「주문 목록을 불러오지 못했습니다 (…).」 | 주문 서비스에 일시적으로 닿지 못했거나 로그인이 끝났다 | 새로 고침. 계속되면 다시 로그인 |
| 「주문을 찾을 수 없습니다.」 | 없는 주문번호다 | 주문번호를 확인한다 |
| 「주문을 불러오지 못했습니다 (…).」 | 주문 서비스에 일시적으로 닿지 못했다 | 잠시 뒤 다시 연다 |
| 「환불 사유를 입력하세요. 고객에게 보내는 환불 안내 메일에 들어갑니다.」 | 환불 사유가 비어 있다 | 사유를 적는다 |
| 「환불 사유는 300자 이내로 입력하세요.」 | 사유가 너무 길다 | 줄인다 |
| 「이미 환불됐거나 환불할 수 없는 상태입니다. 화면을 새로 불러왔습니다.」 | 다른 직원이 먼저 환불했거나, 그 사이 고객이 주문을 취소했다 | 새로 불러온 상태를 확인한다. 환불은 한 번만 실행된다 |
| 「환불에 실패했습니다 (…).」 | 그 밖의 오류 | 잠시 뒤 다시 시도하고, 계속되면 주문번호와 함께 개발 담당에게 알린다 |

## 7. 알아 둘 제한 사항
- 전체 환불 금액 = 결제 금액 − 이미 상품별 취소·반품으로 돌려준 금액. 확인 창의 금액은 안내용이고, 실제 금액은 주문 서비스가 다시 계산한다.
- 「전체 환불」을 두 번 누르거나 두 직원이 동시에 눌러도 환불은 한 번만 된다. 늦게 누른 쪽은 「이미 환불됐거나 환불할 수 없는 상태입니다. 화면을 새로 불러왔습니다.」를 본다.
- 결제는 아직 실제 PG 가 아니다. 「환불」은 주문 서비스의 기록이고 실제 돈이 오가지 않는다.
- 「진행 기록」에는 시각만 남고 **누가 처리했는지는 남지 않는다**(감사 기록은 lee-dohyun/gateway#330 에서 따로 다룬다).
- 운송장 등록과 「배송완료 처리」는 상세가 아니라 목록 화면의 「배송 처리」 칸에서 한다.

## 8. 문의
화면 오류는 개발 담당에게 주문번호(#N)와 함께 알린다.
